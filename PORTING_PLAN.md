## 1. Automatic detection

- **Chosen ABI:** armeabi

- **GLES version:** GLES 1.1 (confirmed, see Phase 3 evidence).

## 1b. Confirmed engine (2026-10-10, evidence below -- replaces the heuristic above)

- **Engine:** Polarbit "Fuse" (`com.polarbit.fuse.*`, `librthunderlite.so`, 1756084 bytes).
- **Sibling port with the same engine:** `Raging-Thunder-2-vita` (Raging Thunder 2,
  `librthunder2lite.so`). Confirmed identical, not assumed:
  - `objdump -T | grep Java_`: 12/12 identical exports (`Jni.*` + `MainTask.FuseOnInit`
    + `MainTask.processTouchpadAsPointer`), same `JNI_OnLoad`.
  - `JniTable` (.data, 0x528 bytes): all 178 pointed-to strings identical in order
    and content between both .so files (dumped with pyelftools VMA->file mapping).
  - UND imports: identical except sibling has `bsearch`+`time` where RT1 has `usleep`
    (all covered by the synced `default_dynlib` union).
  - No `RegisterNatives`; no `pthread_create`; NEEDED = liblog, libdl, libc, libm.
- **GLES 1.1:** sibling's Ghidra finding on the same engine (`CApplication::Init`
  sets 0xb in `PDisplayProperties3D` -> GLES1 branch -> `dlopen("libGLESv1_CM.so")`;
  the string is also present in our .so). GL entry points resolved at runtime via
  `dlopen`/`dlsym` (fuseGL backends SW/ES11/ES20/GL11).
- **Base for this port:** full loader sync from `Raging-Thunder-2-vita`
  (`source/`: main/java/input/overlay/vita_menu/patch/dynlib/reimpl/utils +
  `vendor/vitaGL` + CMakeLists), adapted to TITLEID `PSVRT0001`, slug
  `ragingthunder`, `librthunderlite.so`, `assets/data.vfs`. Sibling state at sync
  time: hardware-tested (menus + races playable, v1.1.1). Its hardware-proven
  fixes come along: VBO-name table (`gl_buffers.c`), FFP `float3` UVs + async
  texture-upload sync (vendored vitaGL), bionic `stat64` layout, `DeleteGlobalRef`
  guard, IME input dialog, `getenv`/`setenv` via newlib, `fseeko`/`ftello` via
  SceLibc, `vfprintf` fake-stdout routing.
- **RT1-specific deltas still open:** `patch.c` car-ground-tint targets
  `CCarActor::Render` (RT2-only; RT1 uses `Car::` classes) -- guarded, warns and
  skips on RT1; port the patch to `Car::` only if hardware shows tinted cars.

## 6. On-console log standard

The game log lives at `<DATA_PATH>logs/<slug>_NNN.log` (`<slug>` = ragingthunder), incrementing
001 to 999 with `next.idx` (never `log_<timestamp>.txt`, never 000-based, never a hardcoded
path: use `DATA_PATH`). The FTP upload creates `logs/` and `saves/` on the console even when
empty. Toolkit commands (no AI, deterministic): `psvita-toolkit log-standard --fix-dirs` (audits
and creates the dirs), `psvita-toolkit log-trace --ensure-flag` (injects per-function
`[TRACE] >> f()` traces under `#ifdef PORT_TRACE`; build with `-DPORT_TRACE=ON` for debug,
`OFF` for production, or `psvita-toolkit log-trace --remove` to strip them from the tree).
